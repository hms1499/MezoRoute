# U11 One Design System and a Dapp Layout: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give MezoRoute one written, test-enforced design system on Geist Mono (Phase 1). Then rebuild the flow pages, the Dashboard, and Positions as a compact Aave/Aerodrome-style dapp layout (Phase 2), without touching how transactions are built.

**Architecture:**
- Tokens stay in `src/lib/ui/tokens.ts` and are written into Tailwind by the existing plugin.
- New scales (radius, spacing steps, control sizes, icon sizes) are added there and replace Tailwind's defaults where a guard needs them, the way U6 replaced `fontSize`.
- Guards are Vitest source scans, as today. `frontend/DESIGN.md` is hand-written, and a parity test pins it to the tokens.
- Phase 2 adds layout components under `src/components/ui/` and `src/components/flow/`, and recomposes existing pages from them. Files under `src/lib/` that build, quote, simulate, or send stay untouched.

**Tech Stack:** Next 14.2.35 static export, React 18.3.1, Tailwind 3, Vitest 5.0.3 (node environment; component tests use `renderToStaticMarkup`), lucide-react, wagmi 2.19.5, viem 2.57.2, and Playwright (MCP server or an exact-pinned dev dependency) for the QA script.

**Spec:** `docs/superpowers/specs/2026-11-06-u11-dapp-ui-design.md`. Read it with this plan; section numbers below (§5.3 and so on) refer to it.

## Global Constraints

- The stack is pinned exactly. Upgrade nothing. The only new dependencies are dev dependencies, exact-pinned: `yaml`, and `playwright` if the QA script uses it.
- Branch: `feat/u11-dapp-ui`. Phase 1 (Tasks 1–11) and Phase 2 (Tasks 12–20) each merge into `main` only on the user's word, because a push to `main` deploys production.
- No change to the colours of the two palettes, to the U10 motion values, or to any file under `frontend/src/lib/` that builds, quotes, simulates, or sends transactions (`tx/`, `quote/`, `trove/`, `gauge/` maths, `positions/exit*`, `routes/`), except where a task names the file.
- One font: Geist Mono, self-hosted with `next/font/local` from `frontend/src/fonts/` with its OFL licence. Never `Inter` or `JetBrains_Mono`.
- Copy rules:
  - an APR always says it is this week's rate;
  - staking copy always says swap fees go to veBTC voters;
  - never "guaranteed" or "earn X%";
  - never annualise the Stability Pool; it shows the text "No fee · BTC from liquidations" (card header) or "BTC from liquidations" (Dashboard returns column);
  - no "≈ $" line.
- Every risk line shown today stays visible before signing: one line plus "Details" on amount pages, the full list on Confirm pages.
- A text pair in either palette reaches 4.5:1 (`contrast.test.ts`). No horizontal scroll at 360 px. Every animation sits behind `motion-safe:`. `WagmiProvider` never re-renders.
- Before every commit run `cd frontend && npm test && npm run build`, and expect both to pass (the build includes lint and type check). Never run `next build` while `next dev` runs. Conventional commits (`feat(frontend):`, `test(frontend):`, `docs:`), each ending with the session's attribution lines.
- QA follows `AGENTS.md`: serve `frontend/out` (`npx serve out -l <port>`; Python's `http.server` resets connections), drive it with Playwright and the keyless mock EIP-1193 wallet. The mock wallet is `frontend/scripts/live/mock-wallet.ts` (Task 11); the 6 Nov audit's throwaway script and screenshots were deleted.

## Review Focus

1. **The 360 px header** with the longest content: mainnet chip, a connected EVM account, dark theme. Expect no horizontal scroll and Connect still visible. Owned by Task 6, which adds a Playwright check at 360 px for both networks.
2. **BTC Max keeps the gas reserve** once the amount field becomes `TokenAmountInput`. Max must fill `balance − reserve`, never the whole balance, and while the gas price is unknown it must stay blocked with a retry. Owned by Task 12 (`tokenAmountMax` test) and Task 15.
3. **A failed gauge read** must not show `0` as a fact in the new stats strips or rows. Expect a "could not be read" notice and wallet-only figures labelled as such (`GAUGE_READ_FAILED_*` copy). Owned by Tasks 18 and 19, with a `gaugeReadFailed: true` fixture test.
4. **Keyboard and focus in the new overlays:** the network menu, the token chip menu, and the slippage popover. Enter or Space opens, Escape closes and returns focus to the trigger, arrow keys move, and nothing is clipped at 360 px. Owned by Tasks 6 and 13; a pure `menuKeys` test plus a Playwright check.
5. **Smart accounts (Bitcoin wallets) in the new cards** still get an approval step instead of a permit. The `0x` relay hash still shows the relayer message. Owned by Task 20's calldata harness, run with the smart-account mock.
