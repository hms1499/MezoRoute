# AGENTS.md

Guidance for every AI coding agent working in this repository (Claude Code, Codex/ChatGPT, Kimi, Gemini, Cursor, …). `CLAUDE.md` and `GEMINI.md` only point here, so there is one source of truth.

## Session protocol (read first)

1. **Start of a session:** read this file, then `docs/STATUS.md` (where the build is, what is next, what waits on the user), then the spec and plan of the task you pick up (`docs/superpowers/specs/`, `docs/superpowers/plans/`). Check `git log --oneline -10` and `git status` against STATUS before acting.
2. **End of a session, or after each milestone:** update `docs/STATUS.md` (done, next, waiting on, decisions still open; add one line to the session log) and commit it. Project state lives only in the repo: tool-private memory (for example Claude Code's `~/.claude/.../memory`) is invisible to other agents, and `.superpowers/` (execution ledgers) is git-ignored.
3. **One agent per branch.** Hand over by committing and updating STATUS; never leave uncommitted work for the next agent.
4. **Never write secrets** (private keys, keystore passwords, API tokens) into any tracked file or chat. `contracts/.env` is git-ignored and holds a testnet-only key; mainnet keys live in an encrypted Foundry keystore (`cast wallet import … --interactive`, then `--account`), run by the user.
5. **Claude-specific lines:** plans start with "REQUIRED SUB-SKILL: superpowers:…" — those are Claude Code skills. Other agents follow the plan's steps (TDD order, commands, expected output) and ignore that line.

## Working agreements with the user

- **Language:** reply to the user in Vietnamese; code, comments, commits, and docs stay in English.
- **Process per feature:** brainstorm → design approved in chat → written spec in `docs/superpowers/specs/` → user reviews → plan in `docs/superpowers/plans/` → user picks the execution method → implement with TDD → final whole-branch review → merge locally into `main` and push (when the user asks).
- **Senior calls:** the user delegates design choices; pick the best option with a one-line reason and ask only questions that change scope or cost. Approval gates (design, spec, plan, merge, anything irreversible such as a mainnet deploy) still apply.
- **QA yourself first:** before handing a checklist to the user, serve `frontend/out` locally and drive it with Playwright and a keyless mock EIP-1193 wallet pointed at real accounts (see `docs/STATUS.md` → QA accounts). Leave only real-wallet steps (Bitcoin wallets, real signatures) to the user.
- **Evidence before claims:** run the real build/test command and read its output before saying something works.

## Contracts (`contracts/`, Foundry)

- Toolchain is pinned to match Mezo: Solidity 0.8.24, `evm_version = london` (Mezo supports London only), `via_ir = true`, **OpenZeppelin 4.9.0** (import paths like `security/ReentrancyGuard.sol`, not OZ 5), Tigris at commit `0a3b5e8` via `@tigris/` remapping.
- **No fork tests.** Mezo's BTC token (`0x7b7C…`) is a chain precompile; on an anvil fork even `balanceOf` reverts. Tests deploy the real Tigris Pool/PoolFactory/Router locally with mock MUSD/BTC (`test/harness/TigrisHarness.sol`). Real-chain behaviour is checked with `script/smoke-testnet.sh` against Mezo testnet.
- `forge script` also simulates locally, so any script that touches BTC fails; use `cast` for live interactions (see the smoke script).
- In tests, build params with `_enterParams`/`_exitParams` **before** `vm.prank` — they make external calls that would consume the prank.
- Run: `cd contracts && forge test`; format with `forge fmt` (`forge fmt --check` must pass before commit).
- Security invariants from spec 11.8 must hold: every payout is a balance delta measured inside the call (pre-existing executor balances are never paid out), exact allowances reset to 0, no owner/admin/proxy, borrowed MUSD recipient is always the caller, recipient may not be the executor or the pool.
- Deploy/smoke secrets live in `contracts/.env` (git-ignored; template `.env.example`). Load with `set -a && source .env && set +a`; never print `PRIVATE_KEY`. `Deploy.s.sol` pins the entry cap per chain (`maxMusdInFor`: mainnet 1,000 MUSD, testnet 1,000,000 MUSD).
- `contracts/SELF_AUDIT.md` maps every spec 11.8 invariant to tests; update it with any change to `src/`.
- The public testnet RPC intermittently returns null receipts — poll instead of failing (see `send()` in the smoke script).

## Frontend (`frontend/`, Next.js 14 static export)

- The app lived in `web/` until 17 Oct 2026 and was renamed `frontend/`; specs, plans, and spikes written before then still say `web/` (and commits used the `web` scope).

- Stack pinned exactly: Next 14.2.35, React 18.3.1, `@mezo-org/passport` 0.17.2, RainbowKit 2.0.2 (Passport's pinned version; a second copy breaks it), wagmi 2.19.5 (Passport does not support wagmi 3), viem 2.57.2.
- iCloud: after a fresh `npm install`, run `xattr -w 'com.apple.fileprovider.ignore#P' 1 frontend/node_modules` so iCloud skips it (npm 11 replaces a `node_modules.nosync` symlink with a real directory).
- `scripts/patch-relayer.mjs` runs on postinstall/prebuild: Passport hardcodes the dead `test.mezo.org` relayer; the live one is `testnet.mezo.org`. Fails loudly if a package upgrade removes the URL.
- The wallet tree is client-only (`next/dynamic`, `ssr: false`); never import Passport, RainbowKit components, or wagmi hooks from a module that `layout.tsx`/`page.tsx` import statically. `next.config.mjs` aliases optional `@x402/*` and React Native storage to `false` and transpiles `@mezo-org/orangekit-contracts` (raw TypeScript) — see the comments there before touching it. The wagmi config and QueryClient are module-level in `providers.tsx`; never build them in render (`useState`), or a discarded first render holds wagmi's reconnect lock and the wallet drops on every reload (found in F2 QA). Never let `WagmiProvider` re-render: without SSR its `Hydrate` calls `reconnect()` on every render, which logged Bitcoin wallets out on each navigation (F3 QA); the page reaches the memoised wallet tree through `PageContext`. OrangeKit's connector rejects wagmi's reconnect (no `chainId`), so Bitcoin wallets go through `withReconnectChain` (`src/lib/wallet/reconnect-chain.ts`). That wrapper also restores the `rkDetails` OrangeKit's connector drops: without them RainbowKit takes the data-URI icon for an EIP-6963 wallet and lists Bitcoin wallets under "Installed" (U7).
- Bitcoin wallets act through an OrangeKit Safe: no `signTypedData` (no permits), gas paid from the Safe's BTC, relayed hash `"0x"` means failure, a confirmed relay can hide an inner revert (`ExecutionFailure`), and relayer outages surface as JSON/fetch errors before any hash — `src/lib/tx/send.ts` and `asRelayFailure` handle all of these. Wallet rejections may be plain `{ code: 4001 }` objects, not `Error`s.
- After any contract change: `cd contracts && forge build`, then `npm run sync-abi` in `frontend/`.
- Run: `cd frontend && npm test && npm run build` (build includes lint and type check). Don't run `next build` while `next dev` is running — they share `.next`. `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID` lives in `frontend/.env.local` (template `.env.example`).
- Vercel project `mezoroute` (the CLI deploys from `frontend/`, where `.vercel/` links it; `vercel.json` sets the Next.js framework). Preview: `cd frontend && vercel deploy --yes --build-env NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID=…`. If `vercel link` appends `.env*` to `.gitignore`, revert it (it would ignore `.env.example`). - Networks: every address lives in `src/lib/config/networks.ts`; mainnet `executor` stays `null` until M1, which makes mainnet read-only. - Dashboard (F2): every read is one multicall snapshot (`src/lib/dashboard/snapshot.ts`), so all values come from one block; each call carries the selected network's `chainId`. Pool `token0` is MUSD on testnet but BTC on mainnet, so reserves are mapped by address. The CR safety floor (160%) and the at-risk rule (a 30% drop below MCR) live in `src/lib/trove/constants.ts`; F4 reuses them. Design: `docs/superpowers/specs/2026-10-05-f2-dashboard-design.md`.
- LP route (F3): the URL carries only user intent (`/route/lp/?amount=&slippage=`); every page re-quotes from one multicall snapshot (`src/lib/routes/musd-btc-lp/snapshot.ts`), refetched every 15 s; a quote expires after 60 s. `src/lib/quote/entry.ts` mirrors Pool/Router rounding exactly (tests replay live S1 `Entered` events). EOAs sign an EIP-2612 permit (domain "Mezo USD", version "1"); smart accounts send an exact approval. `sendCall` is `submitCall` + `confirmCall`; `enter` is simulated with the permit before sending, and the receipt page (`/tx/?hash=`) runs `confirmCall` itself, so reloads keep tracking. `confirmCall` asks again after the testnet RPC misses a mined transaction (null receipt/block) until its 120 s budget. Pre-send checks throw `BlockedError(outcome)`. viem's `multicall3Abi` has no `getBlockNumber`; use `src/lib/abi/multicall3.ts`. Design: `docs/superpowers/specs/2026-10-05-f3-lp-route-design.md`.
- Borrow & Deploy (F4): `mode=borrow` on `/route/lp/` (EOAs only); `musdIn` is the borrowed amount (the contract requires it). Pure maths in `src/lib/trove/{borrow,borrow-signature,hints}.ts`; the borrow authorisation test recovers a live 2 Oct 2026 signature, so a wrong EIP-712 domain or type fails it. Hints are found at send time and fall back to zero hints (≈2.2M gas instead of ≈0.75M). Before sending, a moved BOS nonce means the authorisation was used elsewhere (`BORROW_USED`); that check runs before the gate, whose CR check would otherwise misfire. Recovery mode is computed locally (`systemColl × price / systemDebt < CCR`) because the price is read in the same multicall. Design: `docs/superpowers/specs/2026-10-12-f4-borrow-deploy-design.md`.
- Positions (F7): `/positions/` and `/positions/lp/exit/?percent=&slippage=` (presets 25/50/75/Max; Max is the exact balance). One multicall snapshot (`src/lib/positions/snapshot.ts`) reads the LP, pool balances, and the fee indexes; claimable fees are computed from `claimable + balance × (index − supplyIndex) / 1e18` (`fees.ts`), mapped by token address. `quoteExit` (`src/lib/quote/exit.ts`) burns on pool **balances**, not reserves, and replays live `Exited` events to the wei. Cost basis comes from executor `Entered` (by `recipient`) / `Exited` (by `caller`) logs scanned from `executor.deployBlock` in 10,000-block chunks **clamped to the head** (Mezo returns an empty list, no error, for a range past the head); the `localStorage` cache (`mezoroute.<network>.history.<executor>.<account>`) stores only events ≥ 50 blocks deep, and a failed chunk fails the scan without writing. LP permit domain is name `""`, version `"1"` (the pool is `ERC20Permit("")`). Claim is a direct `Pool.claimFees()` (simulated first). The stepper is generic over step kinds (`Stepper<K>`). viem's `decodeEventLog` ignores `eventName` at runtime (it decodes whichever ABI event the topic matches), so event finders check `decoded.eventName`. `EXIT_GAS` 495,000 from a 417,468-gas permit exit. At send, entry and exit re-check a signed permit against the fresh token nonce (`permitState`): spent elsewhere means sign again, because the executor's try/catch would skip it and the transfer would revert. Design: `docs/superpowers/specs/2026-10-12-f7-lp-positions-design.md`.

- Gas limits: EVM-wallet sends pass a measured budget to `submitCall(config, call, pin, gasBudget)`, which sets `gas = max(budget, estimate × 1.2)` (`gasLimit` in `src/lib/quote/gas.ts`); OrangeKit sends leave gas to the relayer. A testnet RPC backend has answered `eth_estimateGas` with the bare intrinsic gas and returned null for mined transactions (12 Oct 2026), so never let the wallet's own estimate be the only limit. New write paths need a budget constant from a measured transaction. Mezo charges at least **half the gas limit** (a 330,000-limit `provideToSP` used exactly 165,000, 14 Oct 2026), so keep budgets close to measured use instead of padding them. MetaMask ignores the app's `gas` on Mezo mainnet: all six M1 round-trip transactions carried a limit of exactly 3 × the RPC estimate (approve 46,394 → 139,182, while the app sent 60,000), and on testnet (5 Oct) MetaMask used 1.5 ×. MetaMask users on mainnet therefore pay about 1.5 × the real gas (≈0.0000012 BTC for an LP entry). Tightening the app's budgets does not change this. Real mainnet use, from `cast estimate --block <tx block − 1>`: enter 479,120, exit 491,297, SP withdraw 151,240, provideToSP 139,230, claimFees 88,804; these match the testnet budgets.
