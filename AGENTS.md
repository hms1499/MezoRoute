# AGENTS.md

Guidance for every AI coding agent working in this repository (Claude Code, Codex/ChatGPT, Kimi, Gemini, Cursor, …). `CLAUDE.md` and `GEMINI.md` only point here, so there is one source of truth.

## Session protocol (read first)

1. **Start of a session:** read this file, then `docs/STATUS.md` (where the build is, what is next, what waits on the user), then the spec and plan of the task you pick up (`docs/superpowers/specs/`, `docs/superpowers/plans/`). Check `git log --oneline -10` and `git status` against STATUS before acting.
2. **End of a session, or after each milestone:** update `docs/STATUS.md` (done, next, waiting on, decisions still open; add one line to the session log) and commit it. Project state lives only in the repo: tool-private memory (for example Claude Code's `~/.claude/.../memory`) is invisible to other agents, and `.superpowers/` (execution ledgers) is git-ignored.
3. **One agent per branch.** Hand over by committing and updating STATUS; never leave uncommitted work for the next agent.
4. **Never write secrets** (private keys, keystore passwords, API tokens) into any tracked file or chat. `contracts/.env` is git-ignored and holds a testnet-only key; mainnet keys live in an encrypted Foundry keystore (`cast wallet import … --interactive`, then `--account`), run by the user.
5. **Claude-specific lines:** plans start with "REQUIRED SUB-SKILL: superpowers:…" — those are Claude Code skills. Other agents follow the plan's steps (TDD order, commands, expected output) and ignore that line.

## Working agreements with the user

- **Language:** reply to the user in Vietnamese; code, comments, commits, and docs stay in English.
- **Process per feature:** brainstorm → design approved in chat → written spec in `docs/superpowers/specs/` → user reviews → plan in `docs/superpowers/plans/` → user picks the execution method → implement with TDD → final whole-branch review → merge locally into `main` and push (when the user asks).
- **Senior calls:** the user delegates design choices; pick the best option with a one-line reason and ask only questions that change scope or cost. Approval gates (design, spec, plan, merge, anything irreversible such as a mainnet deploy) still apply.
- **QA yourself first:** before handing a checklist to the user, serve `frontend/out` locally and drive it with Playwright and a keyless mock EIP-1193 wallet pointed at real accounts (see `docs/STATUS.md` → QA accounts). Leave only real-wallet steps (Bitcoin wallets, real signatures) to the user.
- **Evidence before claims:** run the real build/test command and read its output before saying something works.

## Frontend (`frontend/`, Next.js 14 static export)

- The app lived in `web/` until 17 Oct 2026 and was renamed `frontend/`; specs, plans, and spikes written before then still say `web/` (and commits used the `web` scope).

- Stack pinned exactly: Next 14.2.35, React 18.3.1, `@mezo-org/passport` 0.17.2, RainbowKit 2.0.2 (Passport's pinned version; a second copy breaks it), wagmi 2.19.5 (Passport does not support wagmi 3), viem 2.57.2.
- The repo moved out of iCloud on 5 Nov 2026 (see Repo conventions), so `node_modules` needs no special handling.
- `scripts/patch-relayer.mjs` runs on postinstall/prebuild: Passport hardcodes the dead `test.mezo.org` relayer; the live one is `testnet.mezo.org`. Fails loudly if a package upgrade removes the URL.
- The wallet tree is client-only (`next/dynamic`, `ssr: false`); never import Passport, RainbowKit components, or wagmi hooks from a module that `layout.tsx`/`page.tsx` import statically. `next.config.mjs` aliases optional `@x402/*` and React Native storage to `false` and transpiles `@mezo-org/orangekit-contracts` (raw TypeScript) — see the comments there before touching it. The wagmi config and QueryClient are module-level in `providers.tsx`; never build them in render (`useState`), or a discarded first render holds wagmi's reconnect lock and the wallet drops on every reload (found in F2 QA). Never let `WagmiProvider` re-render: without SSR its `Hydrate` calls `reconnect()` on every render, which logged Bitcoin wallets out on each navigation (F3 QA); the page reaches the memoised wallet tree through `PageContext`. OrangeKit's connector rejects wagmi's reconnect (no `chainId`), so Bitcoin wallets go through `withReconnectChain` (`src/lib/wallet/reconnect-chain.ts`). That wrapper also restores the `rkDetails` OrangeKit's connector drops: without them RainbowKit takes the data-URI icon for an EIP-6963 wallet and lists Bitcoin wallets under "Installed" (U7).
- Bitcoin wallets act through an OrangeKit Safe: no `signTypedData` (no permits), gas paid from the Safe's BTC, relayed hash `"0x"` means failure, a confirmed relay can hide an inner revert (`ExecutionFailure`), and relayer outages surface as JSON/fetch errors before any hash — `src/lib/tx/send.ts` and `asRelayFailure` handle all of these. Wallet rejections may be plain `{ code: 4001 }` objects, not `Error`s.

- Borrow & Deploy (F4): `mode=borrow` on `/route/lp/` (EOAs only); `musdIn` is the borrowed amount (the contract requires it). - Positions (F7): `/positions/` and `/positions/lp/exit/?percent=&slippage=` (presets 25/50/75/Max; Max is the exact balance). - Gas limits: EVM-wallet sends pass a measured budget to `submitCall(config, call, pin, gasBudget)`, which sets `gas = max(budget, estimate × 1.2)` (`gasLimit` in `src/lib/quote/gas.ts`); OrangeKit sends leave gas to the relayer. A testnet RPC backend has answered `eth_estimateGas` with the bare intrinsic gas and returned null for mined transactions (12 Oct 2026), so never let the wallet's own estimate be the only limit. New write paths need a budget constant from a measured transaction. Mezo charges at least **half the gas limit** (a 330,000-limit `provideToSP` used exactly 165,000, 14 Oct 2026), so keep budgets close to measured use instead of padding them. MetaMask ignores the app's `gas` on Mezo mainnet: all six M1 round-trip transactions carried a limit of exactly 3 × the RPC estimate (approve 46,394 → 139,182, while the app sent 60,000), and on testnet (5 Oct) MetaMask used 1.5 ×. MetaMask users on mainnet therefore pay about 1.5 × the real gas (≈0.0000012 BTC for an LP entry). Tightening the app's budgets does not change this. Real mainnet use, from `cast estimate --block <tx block − 1>`: enter 479,120 (V1) and 496,365 (V2), exit 491,297, SP withdraw 151,240, provideToSP 139,230, claimFees 88,804. V2 on mainnet (6 Nov 2026) cost more than testnet when staking: enter with stake 682,215 (an account's first stake writes fresh gauge storage: +185,850), `enterFromBtc` with stake 511,863, `getReward` 85,049, so those budgets follow mainnet. A budget is max(highest `gasUsed`, highest healthy `eth_estimateGas`) + 5%, rounded up to 5,000, because `gasUsed` is net of refunds (a gauge deposit whose failed receipt shows 143,809 gas used ran out of gas at a 145,000 limit, 5 Nov 2026).
